# Hermes review gate

Approved scope: adapt guiyu/ai-code-review in /Users/weiyi/workspace/ai-code-review for outbound-only private-network review of http://120.26.178.131:3000/halliday/Gitea_code_review (main), using Hermes and private AI API; publish Gitea report before allowing merge; notify PR submitter through Feishu bot DM.

Architecture: Go poller/controller with durable per-run JSON store (single process, exclusive lock), Gitea API client, subprocess Hermes reviewer, deterministic severity gate, independent durable Feishu outbox. No incoming webhook needed for MVP. Only exact repo/base/head/policy generation counts. Missing/error/incomplete output blocks. Source/target must be pinned and verified before/after fetching diff and before publishing success. Require main up-to-date at Gitea. Strict merge controller verifies durable review + current statuses before merge; only its bot in merge whitelist; merge request includes expected head SHA. Target branch changes invalidate result. Never put Gitea/Feishu credentials in reviewer process. Review subprocess receives bounded JSON on stdin, emits exactly JSON stdout. Persistent store and secret config ignored in git.

Reviewer interface input: {"repository":"halliday/Gitea_code_review","number":1,"head_sha":"40hex","base_sha":"40hex","diff":"...","title":"..."}. Output: {"complete":true,"summary":"...","findings":[{"severity":"high","file":"a.go","line":1,"title":"...","evidence":"...","suggestion":"..."}]}. Severity enum critical/high/medium/low/info. Unknown/missing completeness/summary/malformed findings fail closed. Default block critical/high; threshold configurable. Reviewer exit error never approval.

Feishu interface: internal/feishu Client with NewClient(appID,appSecret string) *Client and Send(ctx context.Context, openID, text, uuid string) (messageID string, err error). Expose BaseURL, HTTPClient for local integration tests. Identity mapping from numeric Gitea account IDs (instance-bound config) to bot-app open_id; initial poller notifies PR author (true pusher tracking needs webhook events and is documented). Missing mapping persists error, never silently marks delivery. No real messages during tests without user instruction to test a recipient.

Hermes adapter: Python CLI scripts/hermes_reviewer.py using installed Hermes AIAgent API in isolated per-run home / controlled env; private model configuration passed explicitly via dedicated REVIEW_* env vars. No personal memory/skills or arbitrary repository instructions loaded. Allow bounded read-only context through provided data; subprocess must not inherit credentials; no unsandboxed execution of submitted code. Agentic evidence investigation should use restricted custom read tools or trusted snapshot, not host shell. Report precise limited coverage; fail closed if truncated. Adapter has self-contained unit tests with fake Agent and schema failure cases.

Verification: mock HTTP integration for Gitea, Feishu business errors/idempotency; race/stale result/report failure and restart/outbox tests; reviewer adapter tests; go test -race ./..., go vet ./..., build. Live read-only preflight and protection config readback; no synthetic PR or user notification without explicit test scope. User authorized setting review gate on target repository; authentication may block live configuration.
